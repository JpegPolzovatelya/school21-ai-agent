# MIRROR ME — актуальная подборка для лабораторных

Дата сборки: 2026-09-09.

Эта папка содержит только материалы, которые реально полезны для учебных работ по клиент-серверному взаимодействию, Big Data и связанным дисциплинам. Исходные файлы на диске не перемещались и не удалялись: сюда сделана безопасная копия без `node_modules`, виртуальных окружений, Unity `Library`, сборок, архивов и моделей весом десятки мегабайт.

## Что внутри

### `01_WEBSITE_CURRENT`

Снимок фактически опубликованной версии `edumirrorme.ru`, скачанный 2026-09-09 из публичного сайта и сверенный с файловым менеджером Beget. Внутри — `index.html`, минифицированные JS/CSS и четыре изображения, а также отдельный краткий аудит. Это доказательство текущего деплоя; редактируемые исходники находятся в `01_CLIENT_WEB`.

### `01_CLIENT_WEB`

Наиболее полный найденный локальный frontend Mirror Me: React + TypeScript + Vite. Это маркетинговый интерфейс, а не личный кабинет. В нём нет регистрации, входа, API-клиента и работы с backend. Для клиент-серверной лабораторной его следует использовать как визуальную основу клиента, а не как готовое приложение.

Источник: `/Volumes/jpgplzvtl/08_Старый_снимок_Mac/jpeg_polzovatelya_hz_chto/AR Learning Platform for Autism`.

### `02_EVENT_PRODUCER_PYTHON`

Python-прототип, который создаёт события сессий, сохраняет их в JSONL и строит локальную аналитику. Для лабораторной особенно полезны:

- `src/event_sender.py` — запись события;
- `src/fake.py` — генерация тестовых событий без камеры;
- `src/analytics.py` — чтение и агрегация;
- `tests/` — тесты этих модулей.

`src/main.py` оставлен как контекст происхождения событий. Модели CV в подборку не копировались: для клиент-серверной лабораторной они не нужны, а генератор `fake.py` позволяет воспроизвести поток данных.

Источник: `/Volumes/jpgplzvtl/02_Mirror_Me_проекты/mirror_me/comp_vision_first`.

### `03_EVENT_CONTRACT`

Черновой версионированный контракт событий и архитектурные границы. Это лучшая основа для проектирования REST API и схемы БД. Текущий Python-формат с ним ещё не синхронизирован.

Источник: `/Volumes/jpgplzvtl/02_Mirror_Me_проекты/mirror_me/AR_mirror_me`.

### `04_LAB_REPORTS`

Найденные отчёты по Mirror Me: Big Data и Unity/AR. Это справочные материалы; утверждения о готовности функций нужно сверять с кодом.

### `05_REFERENCE_PLANS`

Старые планы n8n/S3/PostgreSQL/FastAPI. Они описывают намерения, а не реализованную инфраструктуру. Использовать как источник идей, не как доказательство готовности.

### `07_TECHNICAL_SPECIFICATION`

Актуальное подробное техническое задание и пошаговый гайд для production MVP. В разделе находятся редактируемый Markdown, итоговый DOCX, проектный OpenAPI и схемы Mermaid для архитектуры, базы данных и первого сквозного сценария.

## Чего здесь сознательно нет

- FastAPI backend — на диске не найден;
- PostgreSQL-схема, миграции Alembic, Docker Compose — не найдены;
- регистрация, авторизация, JWT/сессии, личный кабинет — не реализованы;
- интеграция с `edumirrorme.ru` — в локальном коде не найдена;
- Telegram-бот Mirror Me — не найден; есть только отправка текстового отчёта из `analytics.py`;
- MAX-бот — не найден;
- RAG — не реализован;
- Unity/Varwin/3D/WebAR — не включены, потому что текущая подборка ограничена лабораторными по клиент-серверной части.

## С чего начать лабораторную по клиент-серверному взаимодействию

1. Зафиксировать минимальный сценарий: регистрация взрослого → вход → создание профиля → запуск учебной сессии → отправка события → просмотр своих сессий.
2. Создать отдельный backend на FastAPI с PostgreSQL и Alembic.
3. Принять `03_EVENT_CONTRACT/EVENT_CONTRACT.md` за основу, но добавить `user_id` только во внутреннюю серверную модель; в клиентском событии использовать псевдонимный `session_id`.
4. Добавить к React-клиенту маршруты `/register`, `/login`, `/dashboard` и единый API-клиент.
5. Подключить `src/fake.py` или небольшой адаптер к `POST /api/v1/events/batch` для демонстрации клиент-серверного обмена.
6. Только после этого добавлять привязку Telegram; MAX оставить следующим адаптером к тому же backend.

## Минимальный результат лабораторной

- `docker compose up` поднимает API и PostgreSQL;
- регистрация и вход работают;
- пароли хранятся только в виде стойкого хеша;
- защищённый endpoint возвращает профиль текущего пользователя;
- события валидируются по версии схемы и сохраняются идемпотентно по `event_id`;
- пользователь видит список собственных сессий;
- есть OpenAPI, ER-диаграмма и автоматические API-тесты;
- секреты лежат в `.env`, а в репозитории только `.env.example`.
